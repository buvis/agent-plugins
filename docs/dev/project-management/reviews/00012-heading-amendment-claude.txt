## Review: PRD 00012 design (heading-promotion amendment)

I read the inline text only. I could not see the diff, so I did not verify that the four promotions are the only edit. The sections `review-policy-v1.json`, `review-evidence-v1.json`, `Validation result and defect codes` and `review-fixtures-v1.json` are now `###` siblings of `### Wire shapes (normative)`. No `####` heading remains.

**Cardinal sins: none triggered.**
- **Deferred authorization:** it is deferred to AP 00018/00020 by named PRD. This design has no actor, write path or state, and it says "A valid evidence artifact does not itself authorize a phase transition".
- **Versioning:** it exists (`schema_version`, `-v1` file names, policy digest pinning). N6 covers the missing evolution rule.
- **Alternatives:** they are recorded in "Reuse and alternatives" and the dated user ruling.

### Checked correct

- **Fixture coverage (Validation result and defect codes, `review-fixtures-v1.json`):** All 29 defect codes appear in at least one fixture. I traced the expected sets by hand for `full-retry-exhausted`, `solo-escalation`, `full-bob-fallback-retry`, `solo-review-free`, `fast-track-delta-missing-eve`, `full-unknown-lane`, `full-finding-as-completion` and `full-findings-without-output`. Each matches the stated rules. The only mismatch is the `full-duplicate-result` reading above.
- **Consensus engine binding (Wire shapes, `profile_binding_mismatch` and the engine paragraph):** The paragraph, the defect rule and the fixtures agree. `full-alice-workflow-unavailable` is accepted. `full-alice-workflow-failed-fallback` and `full-alice-engine-mismatch` are rejected. Under `codex-gemini` the engine must be `legacy`.
- **Lane values between the prose and the wire tables:** Rework caps are 2/1/1. Rosters are alice/blake/bob, alice/blake/eve/bob and alice. The R set has no R5, so the doubt R1–R5 labels cannot collide with consensus R. The fast-track and solo escalation signals match the lane-routing prose.
- **Canonical JSON (Review policy § digest, Wire preamble):** Both use the same `json.dumps` parameters. Wire types allow only integers, so digests are stable across implementations.
- **Heading references:** No broken cross-references that I could find. Remaining references by name ("Reviewer jobs table", "Validation result", "Fixture cases") match existing text. The scoping words in N1 are the only casualty.
