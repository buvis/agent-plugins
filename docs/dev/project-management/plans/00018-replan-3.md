## 1. Budget ruling

| Item | Ruling |
|---|---|
| Acceptance test per task | Every rendered dispatch (Devon, Ivan first and retry, Tess strengthen, deslop, Pat) is at most 50000 bytes. The byte count printed by `render_prompt.py` is the measurement. The cap stays at 50000. The one-trim rule stays. |
| Plan target | Each first render is at most 45000 bytes (10% margin). This leaves at least 5000 bytes for a retry. |
| Estimator budget | `Budget: 75000 tokens per task`. The fixed 55000 overhead plus a 20000-token content allowance (about 80 KB of files, PRD slice and plan text). The highest task below estimates 69146. |
| Why 75000 | The estimator models the worker context window, not the prompt. Any value under 55000 cannot be met. 75000 is the replan-1 value, and every task fits it. The 50000-byte render check is the binding gate. |
| Deviation | Deliberate and user-authorized. The installed halving rule gives `max(40000, 75000/2**2) = 40000` for replan 3. This plan does not apply it. |
| Prompt shaping | Ivan gets the task test file in `FAILING_TESTS`, with a scope header that names the task's node IDs. Support and production files go in `FILE_PATHS` as paths, not inline. Devon gets the task test file plus `controller_owner_support.py` and `controller_cli_support.py` inline, with no trim. Devon's runner command names only the task's node IDs. |
