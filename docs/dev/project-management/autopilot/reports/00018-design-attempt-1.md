# Autopilot controller kernel and protocol design

## Architecture fit

AP00018 introduces the sole portable workflow writer under `plugins/autopilot/controller/`. It does not activate legacy skills or certify a host. AP00019 adds lifecycle/jobs, AP00020 review authority, AP00021 records. OVCAQ remains untouched. Extraction source is OVCAQ commit `cf8be72214a515c84ee42f0d8b30e65cc2a4ebb7`, inspected with `git show`, never checkout HEAD. All tests use temporary roots.

## Module placement

New runtime files: `controller/main.py`, `controller/autopilot_state/{__init__,schema,store,paths,protocol,actors}.py`, relative to the plugin root. New bundle files: `contracts/controller/{workflow-v1,fixtures-v1,provenance}.json` and `contracts/controller-v1.json`. New maintainer exporter: `tools/autopilot/export-controller-contract.py`. Tests: `tests/autopilot/test_controller_{kernel,protocol,actors}.py`. Edit `plugins/autopilot/README.md` and `plugins/autopilot/CHANGELOG.md`. Characterization/ownership/source-to-target maps live in `contracts/controller/provenance.json`; fixture inputs and expected outcomes live in `fixtures-v1.json`. No supervisor or launcher imports.

## Interfaces & contracts

### Kernel

Python floor is 3.12; stdlib only. `autopilot_state.schema` exports `SCHEMA_VERSION = 1`, `MAX_STATE_BYTES = 16777216`, `MAX_COMMAND_PAYLOAD_BYTES = 2097152`, `MAX_STRING_BYTES = 1048576`, `MAX_JSON_DEPTH = 32`, `MAX_JSON_INTEGER_DIGITS = 640`, `SchemaError`, `ResourceLimitError`, `decode_json(text: str, *, source: str)`, `validate_state(value: object) -> dict`, and `new_state(*, repo_root: Path, project_id: str, workflow_id: str) -> dict`. Reject duplicate JSON keys, nonfinite numbers, bool integers, unknown owned fields and unsupported durable versions; validate before deep copying. Default review cap is 2. Reject process identity, PID, launcher, heartbeat, resource usage and TUI state as workflow fields. Model/session observations later arrive only as explicitly bounded workflow evidence, never execution authority.

Retain source `StateStore(path: Path, *, boundary_hook=None)`, `read()`, `initialize(initial)`, `transaction(mutator, *, expected_revision=None, publication_guard=None)`, `restore(*, expected_revision=None, precondition=None)`, source exception names and six `DurabilityBoundary` values. Preserve source lock/read/publication guards, single-link regular-file checks, bounded reads, CAS under exclusive flock, deep-copy mutation, revision increment, fsync-before-replace, backup/state pair repair and create-only initialization. Keep one last-good `.bak` and `.lock`; failed validation/conflict/publication cannot change the pair. Restore requires readable valid current state and valid backup, increments current revision and swaps the pair, matching source; corrupt current state refuses with recovery_required and preserves bytes for operator forensic recovery. Never silently overwrite corruption. Test backup/restore and each injected boundary. Unsupported directory fsync refuses explicitly.

`resolve_project_root(path: Path) -> Path` resolves an existing directory without ancestor workflow inference. The private controller store is `<project-root>/.autopilot/controller/`, directory 0700, with `state.json`, `state.json.bak`, `state.json.lock`, and `actors/`. Before creating any credential, create regular private `.gitignore` files containing `*\n` in both `.autopilot/` and the private controller directory (parent 0700, files 0600; sibling archives are ignored too), refuse an existing incompatible or aliased ignore file, and verify a temporary Git repository ignores state and actor files. This is separate from the implementation batch's legacy state. Reject symlink components below the resolved project root, escapes, nonregular/multiply-linked artifacts and payload-selected state paths. Preserve directory descriptor/no-follow creation and ancestor inode identity rechecks from the pinned root resolver; Path.resolve containment alone is insufficient. Project identity is SHA-256 of the resolved root's UTF-8 path. Relocating the installed package preserves functionality; relocating an existing project requires explicit future migration, not identity rewriting.

Durable state has closed top-level keys `schema_version`, `revision`, `project_id`, `workflow_id`, `repo_root`, `lease_epoch`, `owner`, `actors`, `receipts`, `workflow`. `workflow` is exactly `{batch: null, work: null, tasks: [], review: {cap: 2}, recovery: null, jobs: []}` in this kernel; no operation may mutate these reserves. Later producer PRDs define their expanded schemas and migration. Characterization records each source workflow field and its deferred owner; it does not import process fields or claim full legacy schema equivalence. No generic JSON setter is exported. `owner` is null or `{actor_id, mode, native_session_id, lease_epoch}`; `mode` is `manual|supervised`. `actors` contains descriptors, never credential secrets. `receipts` maps request IDs to canonical request digests, actor binding and complete original responses. `jobs` is empty and cannot be mutated in AP00018. Actor registry retains only the current operator and current owner descriptors (at most two); historical authorizing digests are receipt-owned, never actor rows. Normal receipt admission stops at 4094 entries. Reserve two further slots exclusively for owner.release/owner.recover; these may clear an active owner at saturation, never acquire a new one. At 4096 entries the workflow is sealed against all new mutations; exact receipt retrieval and snapshot remain available. Capacity is an explicit terminal boundary, not an unspecified future repair. Operator exit procedure: finish/reconcile jobs (none supported here), release/recover ownership using reserve capacity, verify an owner-null snapshot, copy the entire private controller directory to a private offline archive and verify every file hash, then rename the original private directory into a sibling private archive named by workflow ID, and open a new workflow at the fixed empty controller path. Never delete the archive. Archived state, credentials, receipts and schema remain replayable by placing the original directory back at its original project binding while the new workflow is offline; never merge identities. README documents the ordered manual procedure; tests saturate normal capacity, clear the owner through reserved capacity, validate the archive/hash/restore roundtrip and open a distinct workflow. No archival or state removal runs automatically. If an active owner reaches hard capacity through externally corrupted state, return recovery_required and retain all evidence rather than overriding it. Top-level `lease_epoch` starts at 0 and increases on acquire/recover/release, retained even while owner is null.

### Protocol

CLI argv is `["python3", "<installed-plugin-root>/controller/main.py"]`. Commands are `--json contract`, `--json snapshot --project-root PATH`, `--json apply --project-root PATH --request FILE`; apply accepts `--actor-file PATH`. No shell invocation or process launch. Request file limit is 2097152 bytes; snapshot/response output limit is 16777216 bytes. Use strict bounded JSON parsing. Exit 0 for success, 1 for structured rejection, 2 for argument misuse; never print credentials or untrusted request values in diagnostics. CLI callers must bound execution time; tests use a 30-second subprocess deadline.

Envelope is exactly `{protocol_major, operation, request_id, expected_revision, project_id, workflow_id, actor_id, job_id, lease_epoch, payload}`. `protocol_major` is integer 1; request_id and nonnull identities are nonempty strings of at most 256 UTF-8 bytes; expected_revision and nonnull lease_epoch are nonnegative integers, never bool. Operator job_id is null. Response is exactly `{ok, revision, result, error_code, retryable}`; success has error_code null and retryable false; failure has result null. Error codes are exactly `invalid_request`, `incompatible_contract`, `revision_conflict`, `wrong_binding`, `missing_capability`, `rejected_evidence`, `recovery_required`. Only revision_conflict is retryable. Rejections retain current revision, or 0 before initialization. Reject malformed envelopes before touching state. Redact diagnostics.

AP00018 implements `workflow.open`, `owner.acquire`, `owner.release`, `owner.recover` and advertises only `workflow.core.v1`. Closed later names are `policy.bind`, `prd.enter`, `task.replace`, `task.start`, `task.finish`, `task.attempt`, `lane.route`, `job.plan`, `job.claim`, `job.record_exit`, `review.record_stage`, `review.close`, `custody.record`, `custody.discharge`, `verification.record`, `phase.handoff`, `prd.stall`, `prd.park`, `prd.defer`, `prd.complete`, `artifact.record`, `records.commit`; these return missing_capability without writes. Unknown operation returns invalid_request. Jobs/reviews/records/waves capabilities are declared unavailable, never advertised or returned as successful stubs.

Payload schemas are closed objects: workflow.open `{}`; owner.acquire `{mode: "manual"|"supervised", native_session_id: nonempty string}`; owner.release `{}`; owner.recover `{reason: nonempty string, reconciled_job_ids: unique string[]}`. Strings obey the identity bound except reason, bounded to 4096 bytes. Freeze schemas and positive/negative fixtures for all four implemented operations. Reserved operation names and their unavailable capability mappings are explicit contract declarations, not implemented payload schemas.

Fresh workflow.open on an absent store alone accepts null workflow_id/actor_id/lease_epoch, null job_id, expected_revision 0 and matching project_id. Assign workflow ID once, create operator credential, state and receipt recoverably under one bootstrap lock. Result contains `workflow_id`, `actor_id`, `actor_file`, `lease_epoch`; only credential path is returned. Initialize receipt and revision 0 together. Identical fresh-open replay after lost acknowledgement returns that exact result without creating credentials or workflows; conflicting ID returns revision_conflict. Existing workflow.open requires a valid actor and all existing bindings; it cannot reset or acquire ownership.

Other apply calls authenticate actor-file against its stored current descriptor or a receipt-retained historical descriptor before any mutation. Check project/workflow binding, scope and job first. For an identical recorded request, either a credential matching the receipt's historical authorizing digest or the authenticated current credential of that same actor_id and role at an epoch not earlier than the authorizing epoch may retrieve only that receipt even if its epoch was revoked; this never grants mutation authority. For any new request, require current descriptor and exact current envelope/credential epoch, then CAS and operation preconditions, then persist state plus receipt atomically. Current-credential receipt retrieval uses the historical envelope unchanged and does not require its lease_epoch to equal the current epoch. Historical credentials cannot submit new operations, altered envelopes or recover ownership. Thus in-place operator-file rotation does not prevent the caller reopening that path and retrieving its original receipt after lost acknowledgement; a caller retaining the old bytes may also retrieve that receipt only. Same canonical complete envelope (including expected_revision) under an authenticated binding returns the original response even after revision changes; changed request ID payload/envelope conflicts. Historical receipt retrieval is the sole exception to execution-epoch revocation and returns no credential contents; it cannot replay effects into new ownership. Retain each receipt's original authorizing digest and response until explicit future migration; capacity refusal never evicts them. Unsupported operation and rejected requests never create receipts or change revisions. Contract/snapshot do not acquire execution ownership; snapshot excludes all credential material.

### Actors and lease

Credential files are strict JSON with closed keys `{actor_id, project_id, workflow_id, role, lease_epoch, native_session_id, secret}`. Generate secrets using `secrets.token_urlsafe(32)`, store only SHA-256 digests in durable actor descriptors, compare with `hmac.compare_digest`. Credential root 0700/file 0600; reject symlinks, hardlinks, wrong permissions and bindings. File contents never enter logs, responses, bundle fixtures or public snapshot. Bootstrap operator is role operator at epoch 0. Execution credential role is owner; its scope allows release and future permitted lifecycle actions, never operator recovery. Future job role is declared but no job credential issuance occurs here.

owner.acquire requires current operator authority and no owner; increment epoch, rotate the operator credential to that epoch, and issue one owner credential bound to mode/native_session_id. Operator actor ID remains stable, its new secret replaces the old secret; every epoch-changing operation rotates it in the same recoverable publication. owner.acquire returns `actor_file`/`actor_id`/`lease_epoch` for the owner and `operator_actor_file` for the refreshed operator. Return its path, actor ID and epoch. Concurrent acquires have exactly one winner; an existing owner blocks even when mode differs. owner.release requires the current owner credential; increment epoch and revoke owner credentials. Preserve operator recovery authority across every acquire/release/recover by rotating its descriptor and credential through recoverable intent; do not make an old execution credential an operator. owner.recover requires operator authority plus reason and reconciliation of the durable active/unreconciled jobs; never timeout alone. AP00018 has no jobs and requires both durable jobs and reconciled_job_ids empty. Increment epoch, revoke prior execution actors and clear owner; acquiring again is explicit. Return current operator credential path/epoch where rotation is required. Lost acknowledgements at every credential publication boundary must leave either the old consistent pair or a recoverable intent; never a committed receipt pointing at missing credential bytes. Recovery retries reconcile intent before new work. Failure to reconcile returns recovery_required without accepting another owner. Intent records contain paths/digests/IDs, never plaintext secrets; staged credential bytes remain private 0600. Use one fixed private `credential-intent.json` and private staged/rollback files under actors. Before changing final credentials, stage+fsync all new bytes and rollback copies, then persist+directory-fsync intent containing the canonical request digest, old revision/state digest, candidate state, response/receipt and old/new credential descriptors/paths/digests. Candidate state contains no secrets. Publish final credential files with fsync/replace/directory-fsync, then publish state+receipt through StateStore, then remove intent and private stages with directory fsync. Bootstrap uses the state sidecar lock without recursively locking; factor a locked initialization entry internally. Never acquire a second flock for the same operation. A crash before durable intent leaves only unreferenced private stages; it changes no final credential or state. A crash after intent is reconciled forward exactly once from validated old/candidate state and verified staged/final hashes, or returns recovery_required retaining evidence. A successful receipt is never emitted until final files match its descriptors. Reconciliation admission: strict envelope and project/workflow binding validation precede reconciliation; only the identical intent request authenticated by its recorded old/new authorizing descriptor (or the identical null-bootstrap request) may finish it. All unrelated/invalid requests return recovery_required/wrong_binding without changing bytes. Snapshot never reconciles; it reports recovery_required while an intent exists. A changed bootstrap request ID cannot reconcile another bootstrap. Frozen fixtures enumerate crashes at stage, intent, each credential publication, state publication and cleanup; after recovery the original caller can retrieve the exact receipt using its historical credential. Rejection byte preservation is measured after admitted intent reconciliation only for that successful matching recovery request; rejected calls never reconcile.

### Export and installed evidence

`contracts/controller/workflow-v1.json` is canonical JSON Schema for durable state and protocol/payload/response definitions. `fixtures-v1.json` freezes named positive/negative scenarios with explicit expected errors and no real secrets. `provenance.json` records OVCAQ repository, exact pin, source-to-target symbol and test maps, hashes, preserved invariants and deliberate exclusions/divergences; preserve MIT attribution in extracted files. Exporter computes SHA-256 of raw schema/fixture bytes and produces `contracts/controller-v1.json`, strict JSON with exactly `{protocol_major, package_version, schema_digest, fixture_digest, operations, capabilities}`. protocol_major is integer 1; package_version equals plugin manifest version; digests are lowercase SHA-256 hex; operations/capabilities are unique string lists containing only implemented items. No symlink path components, regular file, under 16777216 bytes. Runtime contract reads installed assets and matches digests/identities; package version may add `+<build>` only. Export is deterministic and cannot read live workflow state. README documents raw bundle SHA-256 and the single installed argv above. No package version bump/publication or installation is authorized.

## Data flow

CLI parses bounded input → resolves explicit project → acquires store lock → validates contract/binding/auth and intent admission → reconciles only an admitted matching intent → checks receipt then current epoch/revision → validates operation → durably prepares intent/staged credentials → publishes credentials and receipt/state → emits bounded redacted response. Bootstrap shares the same lock with concurrent bootstrap calls. Later operation handlers never bypass the store transaction. Contract export is read-only except its explicit output bundle.

## Reuse inventory

- OVCAQ pinned `src/ovcaq/state/store.py`: extract StateStore durability implementation and exceptions, replacing only schema imports and temporary-prefix branding where recorded. No simplified second writer.
- OVCAQ pinned `src/ovcaq/state/schema.py`: reuse strict bounded JSON and owned-field validation patterns; separate workflow fields and explicit new controller identity/lease/receipt schema. Do not import OVCAQ.
- OVCAQ pinned `src/ovcaq/paths.py`: reuse root/path containment concepts. `state/paths.py` arbitrary mutation is intentionally excluded.
- `tools/autopilot/export-policy.py` and existing contract tests: reuse raw-byte digest/version and installed relocation testing patterns; production imports remain within the plugin root.
- No existing actor/lease/receipt controller implementation found. Searches cover read/load/decode, validate/check/verify, create/init, resolve/lookup and store/state/actor/lease/receipt; existing facade/contracts are known-term controls. Research evidence records exact commands and findings.

## Alternatives considered

1. Smallest diff: import OVCAQ services directly. Rejected: independently distributable package cannot rely on upper layers or source checkout.
2. Copy the whole OVCAQ state machine. Rejected: process/capability launcher/control ownership would become duplicate authority and expose later families prematurely.
3. Chosen: extract tested transaction mechanics, explicitly characterize workflow schema adaptation, add four kernel operations and credential/receipt fence. More work than imports buys standalone relocation and a versioned producer boundary without a second backend.

## Risks & edge cases

Bob is the operator and owner of recovery. No live state migration occurs: the new private store refuses foreign/unsupported schema rather than converting the current batch. Backup/restore tests and immutable package rollback provide recovery; downgrade refuses newer state. POSIX flock/fsync support is required and unsupported filesystems fail explicitly. Credentials prevent accidental cross-role use, not unrestricted filesystem access. Finite receipt capacity preserves replay semantics at the cost of eventual explicit recovery/migration. Next changes are lifecycle/jobs, review policy and record commits; reserved namespaces and durable job reconciliation support them without granting their capabilities now. Bootstrap and credential rotation are the largest crash-consistency risks and require boundary injection. Snapshot may reveal workflow metadata but never secrets. No deletion/export compliance obligation beyond local operator-owned files is introduced; snapshot exports nonsecret state, deliberate project removal is operator-controlled.

## Test strategy outline

First freeze source ownership, source-to-target/test maps and fixtures; then test store/schema/path equivalence, protocol/receipts, actor/lease fencing and installed export. Required scenarios: kernel_field_ownership, contract_examples, kernel_equivalence, concurrent_cas (real subprocesses), corrupt_state_recovery, lease_exclusion, wrong_actor, epoch_revoked, lost_ack_replay, fresh_open_replay, controller_bundle_reproducible, controller_without_upper_layers, contract_bundle_pinnable, unsupported_operation_refused. Test rejected calls preserve raw state/backup/credential bytes, duplicate/NaN/deep/oversized inputs, symlink/hardlink/FIFO/path escape, concurrent bootstrap, every durability/credential intent boundary and operator recovery after owner revocation. Installed tests copy only the plugin into an isolated root, exclude checkout/OVCAQ/Lantern/author-home from imports and environment, and run CLI subprocesses with bounded deadlines. Run PRD's Python 3.12 pytest command and repository validator. Real host execution remains unavailable without separate probe evidence.
