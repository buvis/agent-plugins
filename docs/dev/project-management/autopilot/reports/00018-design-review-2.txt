No cardinal sins. Rollback, secret handling, bounded resources, versioning, owner and alternatives are all present, though some are weak (see findings). I found 3 blockers, 8 non-blockers and 4 questions. I ran no code and changed no files.

## Interface engagement

- **Kernel `StateStore` / `autopilot_state.schema`:** I traced the lock, backup and restore invariants against the receipt and capacity limits (Findings 3, 10, 12). Not checked: the OVCAQ pin `cf8be72`, because that checkout isn't in this repo.
- **CLI protocol (`contract`, `snapshot`, `apply`; envelope, response, error codes):** I traced every failure scenario named in the test strategy to one of the seven codes (Finding 5).
- **Actors, lease and `credential-intent.json`:** I walked the crash and lost-ack paths for acquire, release, recover and bootstrap (Findings 1, 2, 6, 9).
- **Export bundle and exporter:** I checked the design against the repo. `tools/autopilot/export-policy.py` is a 12-line delegate to `plugins/autopilot/scripts/autopilot.py --export-policy`, and the sha256 logic lives in that script (Finding 7). `tests/autopilot/test_package.py:260-278` asserts that the package file set equals the `source-map.json` assets (Finding 8).

 title: "Lost-ack replay fails after in-place operator credential rotation",
 evidence: "Actors/lease: the operator keeps a stable actor_id and its 'new secret replaces the old secret'. Replay: an identical request is served only to 'a credential matching the receipt's authorizing descriptor'. Fixtures: 'the original caller can retrieve the exact receipt using its historical credential'. After a lost acknowledgement for owner.acquire, owner.release or owner.recover, the caller holds only the file now on disk, which carries the new secret. That secret matches the current descriptor, not the old authorizing one, so authentication fails. The old secret exists only in rollback files that are deleted at cleanup. lost_ack_replay therefore cannot pass for operator-initiated operations, and the sentence about the historical credential contradicts the rotation rule.",
 suggested_fix: "Choose one. (a) Receipt retrieval for an identical envelope accepts any descriptor of the same actor_id and role whose epoch is at or after the authorizing epoch. ## Checked and correct

- **Kernel:** The closed top-level keys, the reserved workflow object with no generic setter, and the explicit bans on process and PID fields are consistent with the stated extraction boundary and with Alternatives 1 and 2.
- **Protocol:** Reserved operation names return missing_capability without writes, and unknown operations return invalid_request. Together with "advertises only workflow.core.v1", that gives a clean versioning story.
- **Actors/lease:** Secrets are generated with `secrets.token_urlsafe(32)`, stored as digests, and compared with `hmac.compare_digest`. Intents contain no plaintext secrets. A successful receipt is not emitted before the final credential files match the descriptors.
- **Export:** The bundle has exactly six keys, with digests over raw bytes, a symlink-free read, and deterministic export that does not read live workflow state.
